# WORKFLOW — как агент Cursor ведёт разработку Вайбика

Канонический порядок работы. Если другие документы противоречат этому файлу — прав этот файл (и `AGENTS.md`).
Общие правила сервера — `/opt/docs/AGENTS.md`; этот файл их уточняет для vaybik-hub.

## 0. Режим новичка (главное правило общения)

Алексей — владелец и бэкенд-разработчик, но новичок в терминале и Cursor.

- Объясняй **простым русским языком**: что делаешь, зачем, что получилось. Без жаргона или с пояснением.
- **Не проси Алексея запускать команды** — запускай сам. Просить можно только то, что агент сделать физически не может (оплата, вход в чужой аккаунт, решение «да/нет»).
- **Перед разрушительным действием спроси** и дождись «да»: удаление данных/volume/веток, restore БД, `git reset --hard`, `--force`, миграция с удалением колонок, остановка прода, изменение прод-`.env`.
- В конце каждой задачи — короткий отчёт: «что сделано / что проверено / что дальше / что нужно от тебя (если нужно)».
- Не выдумывай: не знаешь факт сервера — проверь командой (только чтение) или спроси.

## 2. Начало каждого чата

Прочитай: `AGENTS.md` → этот файл → `docs/CONTEXT.md` → последний `docs/devlog/*.md` → `docs/progress.md`.
Затем коротко скажи Алексею, где мы остановились и что предлагаешь сделать.

## 3. Короткие команды Алексея

| Он пишет          | Ты делаешь                                                                        |
| ----------------- | --------------------------------------------------------------------------------- |
| «открой день»     | ритуал открытия (§4)                                                              |
| «закрой день»     | ритуал закрытия (§5)                                                              |
| «задеплой»        | проверки → коммит → push → `scripts/deploy-prod.sh` (§7) → отчёт                  |
| «статус»          | git status, dev-сервер, прод health, что в работе — 5 строк                       |
| «откати»          | откат прода командой, которую напечатал последний деплой (спросить подтверждение) |
| «следующий промт» | взять следующую фазу из `docs/PROMPTS.md`, показать план, после «да» — делать     |

## 4. Открытие дня

1. `date` (Москва). `git status`, `git pull` (ff-only), `npm install` если менялся `package-lock.json`, `npx prisma migrate dev` если есть новые миграции.
2. Проверить окружение: dev-БД `healthy`, dev-сервер отвечает на :3000, `git push --dry-run` проходит, прод `/admin/api/health` = 200. Сломано — починить (своё) или записать риск.
3. Прочитать `docs/CONTEXT.md`, последний devlog, `docs/progress.md`.
4. Создать `docs/devlog/<сегодня>.md` по шаблону (§6) и заполнить «План на день» (3–7 пунктов).
5. Коммит `docs: devlog <дата> — открытие дня`, push. Сообщить Алексею план.

## 5. Закрытие дня

1. Довести шаг до рабочего состояния или откатить незавершённое (в main не оставлять сломанное).
2. `npm run lint && npm run typecheck && npm test` (и `npm run build`, если трогали сборку/конфиг).
3. Коммиты + `git push`.
4. Если есть готовое и проверенное — деплой (§7) и проверка прода.
5. Дописать devlog: Сделано / Решения / Проблемы / Дальше / Риски / Коммиты.
6. Обновить `docs/progress.md` (галочки) и `docs/CONTEXT.md` (текущее состояние, новые решения, следующие шаги).
7. Коммит `docs: devlog <дата> — закрытие дня`, push. Отчёт Алексею в 5–8 строк.

## 7. Ежедневный цикл разработки

- Работаем в `main` маленькими шагами (одиночная команда, CI в GitHub Actions). Большую рискованную переделку — в ветку `feat/<имя>`, потом fast-forward в main.
- Перед **каждым** коммитом: `npm run lint && npm run typecheck && npm test`. Перед деплоем и концом фазы — ещё `npm run build` (и `npm run test:e2e` для фаз).
- Коммиты — Conventional Commits: префикс на английском (`feat`, `fix`, `docs`, `test`, `chore`, `refactor`, `ci`), описание **по-русски**, по смыслу: `feat(vault): папки и теги`. Один логический шаг = один коммит. Без секретов.
- Миграции: `npx prisma migrate dev --name <что>` — коммитить вместе с кодом. Удаление колонок/таблиц — только с вопросом Алексею.
- Новые переменные окружения: в `.env.example` (пустые), в dev `.env` — сам; в прод `.env` — **только добавлять новые ключи**, существующие секреты не трогать и не печатать; сказать Алексею.
- После шага — отметить в `docs/progress.md`.

### Как коммиты попадают на GitHub

У пользователя `deploy` есть ключ `~/.ssh/id_ed25519_github_vaybik_hub`, он добавлен в репозиторий как **deploy key с правом записи** (`~/.ssh/config`: Host github.com). Значит: `git push origin main` из `/opt/vaybik-hub` работает сам. `git push --force` и переписывание истории запрещены.

### Деплой в прод

```bash
scripts/deploy-prod.sh --dry-run   # что поедет, есть ли миграции
scripts/deploy-prod.sh             # проверки → тег prev-<sha> → pull → build → up -d → health
```

Скрипт выкатывает `origin/main` (сначала push), требует, чтобы dev был на том же коммите, сам прогоняет lint/typecheck/test, ждёт healthy и `https://vaybik.ru/admin/api/health`. В конце (или при ошибке) печатает **команду отката** — сохрани её в devlog.

- Откат = прежний образ; **миграции БД он не отменяет**. Деплой с миграциями, удаляющими данные, — только после ручного бэкапа (`docker compose exec worker npx tsx scripts/backup-now.ts` в прод-папке) и «да» от Алексея.
- После деплоя: открыть https://vaybik.ru/admin/login (curl 200), посмотреть `docker compose logs --tail 50 app` в прод-папке, записать в devlog.
- Без явной просьбы не деплой в ночь/перед уходом, если не можешь проверить результат.

## 8. Новый сервис на поддомене (chat.vaybik.ru, lead.vaybik.ru, …)

1. Отдельный проект и репозиторий: `new-project <имя> --stack node|python|static --client "Вайбик" --purpose "..." --up` → `/opt/apps/<имя>`, `https://<имя>.vaybik.ru` (wildcard DNS, сертификат сам). Подробно — `/opt/docs/DEPLOY.md`.
2. Compose: только сеть `proxy` + своя внутренняя, **без `ports:`**, labels Traefik: `Host(<имя>.vaybik.ru)`, entrypoint `websecure`, `tls.certresolver=le`, http-роутер с `to-https@docker`. Генератор labels есть в админке (Сервисы → Traefik labels). Плюс label `vaybik.managed=true` (для фазы 2).
3. Эндпоинт `/health` (200 JSON). Секреты — только `.env` сервиса (chmod 600), копию — в Vault админки.
4. GitHub-репозиторий `bilarius1-tech/<имя>`: создать (нужен gh/браузер Алексея или бот Grok) и добавить deploy key сервиса — у deploy key доступ только к одному репо, поэтому на каждый репо свой ключ `~/.ssh/id_ed25519_github_<имя>` + `Host github-<имя>` в `~/.ssh/config`. Если не можешь сам — попроси бота Вайбика (Grok) в чате, не Алексея в терминале.
5. Зарегистрировать в хабе: https://vaybik.ru/admin/services → «Добавить» (имя, URL, healthUrl, контейнер) или `scripts/seed-services.ts`. Проверить, что на дашборде статус «up».
6. Записать сервис в `docs/CONTEXT.md` → «Сервисы».

## 9. Безопасность (кратко, полностью — `.cursor/rules/10-security.mdc`)

- Никогда: `acme.json`, `/opt/proxy` (конфиг Traefik), `/etc/amnezia/*`, `/opt/xray`, `sshd_config`, ufw/firewall, чужие проекты в `/opt/apps`.
- Не печатать секреты в чат/лог/devlog/коммиты. Прод `.env` — только добавление новых ключей.
- Запрещено: `docker system prune -a`, `docker volume rm` прода, `rm -rf` вне проекта, `git push --force`, `curl | sudo bash`.
- Docker из приложения — только через socket-proxy.
